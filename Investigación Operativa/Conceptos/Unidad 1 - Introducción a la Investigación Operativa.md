# Unidad 1 - Introducción a la Investigación Operativa

La Investigación Operativa usa modelos matemáticos para apoyar la toma de decisiones. Su objetivo es representar un problema real, analizar alternativas y encontrar una solución eficiente según un criterio definido.

No reemplaza la decisión humana: la estructura. El modelo ayuda a ver consecuencias, restricciones y tradeoffs que no siempre son evidentes.

## Etapas de un problema de IO

1. Identificar el problema real.
2. Recolectar datos relevantes.
3. Formular el modelo.
4. Resolver el modelo.
5. Validar si la solución tiene sentido.
6. Interpretar los resultados.
7. Implementar o recomendar una decisión.

## Modelos

Un modelo es una representación simplificada de la realidad. No incluye todo: incluye lo necesario para decidir.

Tipos centrales:

- Determinísticos: los datos son conocidos o se asumen fijos.
- Probabilísticos: hay incertidumbre y se usan probabilidades.

[[Unidad 2 - Programación Lineal]] suele trabajar con modelos determinísticos. [[Unidad 4 - Simulación Estocástica]], [[Unidad 5 - Fenómenos de Espera]] y parte de [[Unidad 7 - Modelos de Inventario]] incorporan incertidumbre.

## Campo de aplicación

La IO aparece en producción, logística, inventarios, asignación de recursos, planificación de proyectos, colas de espera, transporte, finanzas y decisiones competitivas.

En informática, sirve para optimizar procesos, planificar recursos, diseñar sistemas de apoyo a decisiones y evaluar alternativas con criterios cuantitativos.

## Cómo explicarlo

"Investigación Operativa es una disciplina que usa modelos matemáticos para apoyar decisiones. Primero se identifica un problema real, se lo traduce a un modelo con variables, restricciones y un objetivo, se resuelve con una técnica y después se interpreta la solución. La clave es que el modelo no es la realidad completa, sino una simplificación útil para decidir."

## Errores típicos

- Confundir el resultado matemático con una decisión automática.
- Modelar sin entender el problema real.
- Usar datos sin validar.
- No interpretar la solución en unidades del problema.
- Olvidar que todo modelo simplifica la realidad.
