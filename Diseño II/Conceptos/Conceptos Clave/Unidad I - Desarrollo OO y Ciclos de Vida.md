# Unidad I - Desarrollo OO y Ciclos de Vida

La Unidad I funciona como base conceptual de Diseño II. Antes de entrar en [[Proceso Unificado de Desarrollo]], [[RUP]], metodologías ágiles, patrones o Design Thinking, hay que poder explicar por qué el desarrollo de software necesita procesos, qué problema intenta resolver cada ciclo de vida y qué aporta la orientación a objetos como forma de analizar y diseñar sistemas.

Para el oral, esta unidad no conviene estudiarla como una lista de definiciones. Conviene estudiarla como una historia:

1. El software se vuelve complejo.
2. Esa complejidad exige métodos de trabajo.
3. Los primeros ciclos lineales dan visibilidad, pero reaccionan mal al cambio.
4. Los ciclos iterativos e incrementales permiten aprender antes y reducir riesgos.
5. La orientación a objetos ayuda a modelar el dominio con responsabilidades, colaboraciones y abstracciones.
6. El Proceso Unificado toma estas ideas y las ordena en fases, iteraciones, arquitectura, casos de uso y gestión de riesgos.

## Guion oral de la unidad

"La Unidad I introduce el problema de cómo desarrollar software de forma controlada. A medida que los sistemas se vuelven más complejos, no alcanza con programar: hace falta una metodología que ordene actividades, permita repetir resultados y reduzca riesgos. Los ciclos de vida lineales, como cascada, organizan el trabajo en etapas sucesivas y dan visibilidad, pero funcionan bien solo cuando los requisitos son estables. Cuando hay incertidumbre, convienen enfoques iterativos e incrementales, porque producen prototipos o incrementos evaluables y permiten corregir antes. Sobre esa base aparece el desarrollo orientado a objetos, que modela el sistema como objetos con responsabilidades y colaboraciones. Todo esto prepara el terreno para el Proceso Unificado, que combina iteración, arquitectura, casos de uso y gestión de riesgos."
